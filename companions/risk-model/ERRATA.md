# Errata and Improvement Register — PGF v1 risk model (companion 0.1.0-preview.1, 27 October 2026)

**What this register is.** It records points where the accepted PGF v1 text (content baseline `02ff78357f3b24f607651f0bf9f01c6c279b587b`) appears ambiguous, internally inconsistent or open to improvement. It was found while the model was being formalised and tested.

**What it is not.** It does **not** change PGF v1, and the companion reproduces v1 as written. Each entry gives the evidence, the readings, the effect on the v1 worked example and a proposed resolution, for a future decision by the PGF authors. Line numbers refer to the baseline files.

**Statuses:**
- **candidate defect** — the v1 text and a v1 example disagree, or a rule is incomplete;
- **clarification** — the text admits two readings and the examples do not settle them;
- **improvement** — v1 is consistent, but a change would strengthen it;
- **implementation note** — not a defect; a hazard for anyone implementing the model.

| E-01 | candidate defect | Likelihood override and inherent likelihood | PGF-18 Part A §3.2: "where a control is absent or ineffective (L3 = 3) against a capable or systematic threat source (L2 ≥ 2), the likelihood level is at least High, whatever the index". The inherent likelihood is defined with L3 = 3. PGF-19, DPIA-FL-01 S2: L1 1 + L2 2 + L3 3 + L4 0 = 6 → "Medium" (inherent). | Under the literal rule, the inherent likelihood of FL S2 is High; the inherent tier of S2 and of DPIA-FL-01 is then High, and PRR-FL-01 reads High → Medium rather than Medium → Medium. All other v1 inherent calculations with L2 ≥ 2 already have an index ≥ 7, so this is the only divergence. | State whether the override applies to the inherent value. If it does, correct DPIA-FL-01 S2 (inherent) and PRR-FL-01 (inherent). The companion follows the v1 example and records the literal reading as an alternative (RM-EX-05). |
| E-02 | clarification | Severity floor (i): Art. 9 only, or Art. 9 and Art. 10? | PGF-18 Part A §3.4, floor (i): "identifiable special-category data". The Factor B "special categories" sub-factor groups Art. 9 and Art. 10 data, but PGF-10 states that criminal-offence data are not a special category. | None for the current PSI S1 (index 8, already Significant). The superseded March 2026 PSI calculation (index 6) would have been raised to Significant by the floor under the wider reading. | State whether floor (i) covers Art. 10 data used to make decisions about the person. The companion uses the literal (Art. 9 only) reading. |
| E-03 | clarification | Data-age modifier below zero | PGF-18 Part A §3.4 (Data Class): the data-class score "may be reduced by 1"; Public scores 0; only the total index is floored at 0. | None; no v1 example uses the modifier. | Floor the reduced data-class score at 0, or exclude Public from the modifier. |
| E-04 | clarification | Classification of PSI (archetype 3 or 4) | PGF-18 archetype 3 includes "intersection result" artefacts. DPIA-PSI-01 is run under Project 4 (identified processing), with the one-sided design (no output to the partner). | None as written. | State whether protocol messages that reach the partner in a one-sided PSI are assessed as an archetype-3 disclosure scenario with a PET-module outcome, or through L3 and TIA evidence only. |

| E-06 | improvement | Reporting of attack metrics | The PET module uses orientation-invariant AUC/accuracy gates with confidence bounds. An average over thresholds can hide exposure at low false-positive rates (research layer, LC-26 / RX-17). | None. | Add TPR at a fixed low FPR as a reported (not gating) metric for membership tests. |
| E-07 | improvement | Adjacency in parallel composition | Where disjoint partitions are composed by the maximum, the result holds under add/remove adjacency with a data-independent partition; under replace-one adjacency a label change affects two partitions (LC-20 / RX-15). | None found in the v1 example. | State the adjacency relation wherever parallel composition is relied on (PGF-18 §3.3.5–3.3.6). |
| E-08 | improvement (external validity) | Ordinal severity versus actual size of harm | The severity index is built from attributes: data class, scale, reach, provenance and so on. In RM-EX-01 (artificial) a scenario whose harm includes financial loss through convincing phishing scores index 3 → Minor, and every tier is Low. The arithmetic follows v1 exactly. | None on v1 decisions. The risk is reader misinterpretation: "Minor" is the output of a conditional ordinal scale, not an independent estimate of how much money a person could lose. | State in PGF-18 that the index is not a consequence estimate. Ask adopters to add a consequence check — for example a plausible worst-case loss per person and whether it is reversible — before relying on a Low tier. A future version could let such a check lift the level through a recorded, reasoned uplift, as the existing severity floors already do for listed cases. The PGF scales and matrix stay unchanged; the companion documents this as a limitation (docs/01, docs/03 RM-EX-01, docs/04). |
| E-09 | candidate defect | Incomplete DP statement reported as PASS | PGF-18 Part A §3.3.5 lists the minimum elements of a DP statement, including implementation assurance (how the implementation was verified; floating-point and sampling hazards addressed) and the limits of empirical tests. G-M4 (§3.3.0) fails the module when the statement is incomplete. The Part B Project 2 passport's DP statement (Ex 2.1-R) gives the privacy unit, adjacency, mechanism, accountant, δ and n, output access and the ledger, but not implementation assurance or empirical limits. Ex 2.1-R nevertheless records "Module outcome: PASS". The same applies to DPIA-FL-01 (PGF-19, summary table): its DP statement gives the privacy unit, clipping and noise placement, the accountant, ε/δ and the ledger, but not the adjacency relation or implementation assurance, and the module outcome is reported as PASS. PGF-19 notes that these DPIAs are "not reproduced in full", so the complete statement may sit in the evidence pack. | Under the clause as written, both PET module outcomes are FAIL (G-M4). The companion follows the clause (RM-EX-03D, RM-EX-05A) and records v1's reported PASS and tiers alongside it. | Either complete the DP statements in the Project 2 passport and the DPIA-FL-01 summary, so that the examples remain PASS, or state that a passport or summary may reference a complete DP statement held in the evidence pack. |
| E-10 | clarification | Meaning of "as proposed" for the inherent value of PET-module scenarios | PGF-18 Part A §3.2 defines inherent likelihood for the threat-based model (L3 assessed as 3, i.e. without measures). For PET-module scenarios, the inherent value is defined only in the PGF-22 glossary: "the PET Assessment Module as proposed". It is applied in PGF-19 (DPIA-CS-TRAIN-01, "inherent Medium") and PGF-22 (PRR-FL-01, "Medium → Medium"). PGF-18 does not say what "as proposed" means when the PET measure is itself the control being assessed. | None on residual tiers or decisions. Where the as-proposed configuration equals the assessed one, inherent and residual PET likelihoods coincide, so the inherent value says little about how much the measure matters. | State in PGF-18 what "as proposed" means: for example, the module result for the design before any additional measures, or the same disclosure scenario with the PET measure absent. The companion follows PGF-22: inherent = module on the as-proposed configuration where the input supplies one, otherwise on the assessed configuration, labelled as such. |
| N-01 | implementation note | Exact arithmetic for weighted indices | PGF-18 Part A §4.3: fractional indices map to bands "without rounding". Binary floating point gives 0.7·2 + 0.7·3 = 3.4999…, which would fall in Minor instead of Moderate. | — | Implementations must use exact decimal or rational arithmetic (the reference code does). |
